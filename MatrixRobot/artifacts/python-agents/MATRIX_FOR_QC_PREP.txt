■ الهدف
────────────────────────────────────────────────────────────────────────────
فحص وإرشاد — ليس «إصلاح تلقائي». QuantConnect يختبر المنطق الذي ننقله
(port) من Matrix ويعطي أرقاماً ومقترحات؛ أنت تطبّق التعديلات في Matrix/VPS.

■ نسبة التغطية التقريبية
────────────────────────────────────────────────────────────────────────────
  ~55–60%  → QuantConnect (backtest تاريخي)
  ~40–45%  → منصات أخرى (GPT live، scalp حي، MT5، سجلات VPS) — لاحقاً

================================================================================
3) المطلوب منك قبل أول backtest
================================================================================

  [أ] حساب QuantConnect
      • تسجيل على https://www.quantconnect.com
      • Organization + مشروع Algorithm (Python)

  [ب] اختيار بيئة التشغيل (واحدة)
      • المتصفح — Cloud Backtest (الأسهل للبداية)
      • Lean CLI محلياً — يحتاج User ID + API Token من صفحة الحساب

  [ج] لا نرفع أسرار Matrix إلى QC
      • لا مفاتيح API، لا .env، لا MT5 credentials
      • ننقل المنطق والأرقام الافتراضية من config.py فقط (قيم عامة)

  [د] قرارات إعداد (أنت تختار — لا نفرض تواريخ ولا رموز محددة هنا)
      • فترة الاختبار: من واجهة QC عند إنشاء/تشغيل الـ backtest
      • الرموز: كل ما في settings.symbol_list أو subset تختاره
      • الإطار الزمني: H1 افتراضي (يطابق Matrix intraday) — قابل للتغيير
      • profile: FN_CHALLENGE | FN_FUNDED | REAL (من config)

  [هـ] موافقة خطوة بخطوة
      • أي تعديل على Matrix/VPS/.env — فقط بعد موافقتك الصريحة

6) مخرجات الفحص (ما ستحصل عليه)
================================================================================

  • Profit Factor، Win Rate، Max Drawdown لكل رمز
  • عدد الصفقات المرفوضة لكل طبقة (council vs risk)
  • أي رمز يجرّ المحفظة للأسفل
  • مقارنة تشغيل «ensemble فقط» vs «ensemble + council + risk»
  • قائمة مقترحات — ليست تعديلات تلقائية على VPS
